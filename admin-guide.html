第二屆 GISA 創櫃菁英選拔　決選評分系統
前往後台監控 評審專屬連結 評審委員操作說明
這份手冊目前是從電腦裡的檔案開啟的，所以站內連結（後台監控、評審專屬連結、評分頁面） 已暫時隱藏——那些頁面在評分系統網站上，本機資料夾裡找不到，點了會出現「找不到檔案」。
內容照樣可以閱讀與列印；要使用那些頁面，請改從主辦單位提供的評分系統網址開啟本手冊。

一、試算表選單在哪裡 所有日常維護都在這個選單裡，安裝完成後不必再進 Apps Script 編輯器

選單在 Google 試算表本身的最上排功能表，位置在「說明」的右邊，名稱是 GISA 評分系統：

檔案編輯查看 插入格式資料 工具擴充功能說明 GISA 評分系統
↑ 就在這裡（在試算表畫面，不是在 Apps Script 編輯器畫面）

沒看到選單的三個原因

  1. 試算表分頁是在貼上程式之前開的 → 把該試算表分頁重新整理一次。 掛選單的程式只在「開啟試算表」的當下執行，程式貼上去的當下不會自動出現。
  2. 第一次使用需要授權 → 點下任一選單項目後，跟著 Google 的授權畫面按到底 （會出現「這個應用程式未經驗證」，點「進階」→「前往…（不安全）」是正常流程， 因為這支程式是您自己寫的）。
  3. 在 Apps Script 編輯器裡找 → script.google.com 的編輯器畫面 永遠不會有這個選單，請切回試算表分頁。

七個選單項目

二、活動當天怎麼盯後台網址：…/admin.html?key=您的金鑰

  1. 開後台。用選單「顯示後台金鑰」取得完整網址，或直接開 admin.html 後輸入金鑰。 後台每 5 秒自動更新，不必一直重新整理。
  2. 盯最上方兩張卡。「評分完成度」看還有幾格沒填、「最終確認」看還有幾位委員沒送出。 兩張都滿了就代表評分階段結束。
  3. catch 落後的委員。切到「評審進度」分頁，最下方的「尚未完成的評分」 會明白列出誰還沒評哪幾家，可以直接去提醒。
  4. 看結果。「最終成績表」就是最終排名，同分時系統會自動依決勝規則排序。
  5. 留存。按工具列的「匯出 CSV」下載完整資料存檔；原始資料同時也在 Google 試算表裡。
i 投影模式可以把後台放到大螢幕給評審或來賓看（字級加大、深色底）。 要注意投影出去會顯示各公司分數，請自行斟酌時機。

三、後台六個分頁在看什麼

分頁內容
最終成績表 預設看到的那一頁，就是最後要用的成績表。每家公司的各構面平均、總平均、名次， 已評人數會自動扣掉利益迴避的評審。同分時依「總分 → 產品創新＋市場需求 → 市場需求 → 產品創新」自動決勝。
即時排名評分過程中的即時名次變化，適合邊評邊看。
評分矩陣每位評審給每家公司的總分，顏色深淺代表高低；斜線代表還沒評、「迴避」代表利益迴避。
構面分析各公司五大構面的得分組成，看得出來是贏在哪個構面。
評審進度每位評審的進度、平均、全距、標準差（看得出寬嚴與鑑別度），以及「尚未完成的評分」清單。
評語彙整所有委員意見，可依公司篩選，適合會後整理回饋給參賽公司。
✓ 不需要再自己拉公式算名次。「最終成績表」已經把平均、名次、同分決勝、 以及利益迴避造成的人數差異全部算好了，並可直接匯出 CSV。

四、常見任務怎麼做

評審不小心按了最終確認，要重新開放修改
  1. 試算表選單 →「解除某位評審的最終確認」
  2. 輸入該評審的完整姓名職稱（例如 簡立忠董事長，要跟名單上一字不差）
  3. 請該評審把評分頁面重新整理一次，就能繼續修改了
新增或修改評審委員
  1. 在「評審名單」工作表直接新增一列：A 欄單位、B 欄姓名職稱
  2. 選單 →「重新整理名單快取」（不做的話最多要等 5 分鐘）
  3. 選單 →「設定 GitHub Pages 網址」重新產生連結，或直接開 links.html 取得該委員的連結與 QR Code
設定利益迴避（某位評審不評某家公司）
  1. 在「迴避名單」工作表新增一列：A 欄選評審、B 欄選決選公司（都是下拉選單），C 欄可填備註
  2. 選單 →「重新整理名單快取」
  3. 該評審重新整理頁面後，這家公司會顯示「利益迴避」且無法評分； 他的應評家數與最終確認都會自動扣掉，後台的完成度分母也會跟著減少
i 公司名稱要跟「公司名單」完全一致。若打錯字，後台「最終成績表」上方會跳出黃色提醒告訴您哪一列對不到。
彩排結束，要清掉測試分數
  1. 選單 →「清空所有評分」→ 在確認視窗按確定
  2. 會清空「評分明細」與「最終確認」兩張表，公司、評審、迴避名單都不受影響
  3. 若名單裡還留著「測試評審」，正式活動前可以把該列刪掉，再執行一次「重新整理名單快取」
產生／發送評審專屬連結
  1. 選單 →「設定 GitHub Pages 網址」，輸入評分系統網址（例如 https://帳號.github.io/repo/）
  2. 連結會自動回填到「評審名單」C 欄，也可以打開 links.html 看到每位委員的連結與 QR Code
  3. links.html 按「列印 / 存成 PDF」可印成連結卡，或直接用 LINE／Email 個別發送
忘記後台金鑰
  1. 選單 →「顯示後台金鑰」，視窗會同時顯示金鑰與後台完整網址

五、改過程式一定要重新部署這是最容易踩、而且不會報錯的坑

Apps Script 在編輯器改完程式並存檔之後，對外服務的網址仍然在跑舊版程式碼。 症狀是畫面一切正常、沒有任何錯誤訊息，但新的權重或迴避設定就是沒生效。

正確的重新部署步驟

  1. Apps Script 編輯器右上角 → 部署
  2. 選 管理部署作業（不是「新增部署作業」）
  3. 右上角的鉛筆圖示（編輯）
  4. 「版本」下拉選 新版本
  5. 按 部署
! 不要用「新增部署作業」。那會產生一個全新的網址， 您得回頭把 index.html、admin.html、links.html 三個檔案裡的 API_URL 全部改掉，否則系統會連到舊的後端。
! 後台最上方出現紅色的「後端版本過舊」→ 就是這個狀況：程式改了但沒重新部署。 照上面五個步驟做完，重新整理後台即可。
⚠ 後台最上方出現琥珀色的提醒（「沒有回報版本號」）→ 代表 Apps Script 上的程式碼 比網站上的舊。若您沒有修改過計分規則，分數與名次仍然是正確的，可以照常使用。 要讓提醒消失，請把 repo 的 apps-script/Code.gs 全選複製、貼進 Apps Script 編輯器覆蓋、存檔，再照上面五個步驟重新部署。
兩種橫幅都可以按右上角的「知道了」暫時關掉（重開分頁會再出現），不影響任何計分。

六、計分規則備忘

權重與填寫順序（2026 年度）

表格由上而下就是評審在畫面上填寫的順序；試算表「評分明細」的欄位順序也一樣。

構面上限
市場需求與規模35 分
技術門檻20 分
產品創新與行銷30 分
經營團隊10 分
財務狀況5 分
合計100 分

可填到小數點後兩位。要調整權重需修改 Code.gs 與兩個網頁檔，改完務必重新部署。

同分決勝

總分相同 → 比「產品創新＋市場需求」的合計 → 再同分 → 比「市場需求」→ 再同分 → 比「產品創新」。 四項全部相同才視為並列。後台「最終成績表」已依此規則自動排序。

利益迴避對計分的影響

  • 該評審的應評家數減少（例如 10 家 → 7 家），少評的不算他缺交。
  • 被迴避公司的已評人數分母也減少（例如 8 位 → 7 位）， 平均分以實際評分的人數計算，所以不會因為少一個人評而吃虧。
