# 第二屆 GISA 創櫃菁英選拔 — 決選評分系統

前端純靜態（GitHub Pages），後端 Google Apps Script + Google 試算表。
評審用專屬連結打分，主辦單位用後台即時監控所有人的分數與各構面表現。

| 檔案 | 用途 |
|---|---|
| `index.html` | 評審評分頁（`?judge=姓名職稱`） |
| `admin.html` | 後台即時監控（`?key=後台金鑰`） |
| `links.html` | 產生各評審專屬連結與 QR Code，可列印 |
| `assets/qr.js` | QR Code 產生器（純前端，無外部服務） |
| `apps-script/Code.gs` | 後端程式，貼進 Google 試算表的 Apps Script |

---

## 一、安裝（約 10 分鐘，只要做一次）

### 1. 建立試算表與後端

1. 開一份新的 Google 試算表（或沿用舊的）。
2. 「擴充功能 → Apps Script」，把 `apps-script/Code.gs` 的內容整份貼進去，**存檔**。
3. **⚠️ 最容易踩到的一步**：看編輯器上方工具列，「執行 / 偵錯」右邊有一個**函式名稱下拉選單**。

   ```
   ▷ 執行    ↻ 偵錯    [ setupSheets ▾ ]    執行記錄
                        ↑ 這裡必須是 setupSheets
   ```

   如果顯示的是 **`doGet`**（或其他名字），**先點下拉選單改成 `setupSheets`**，再按「執行」。
   第一次會要求授權，允許即可。

   > 為什麼會踩到：編輯器預設選檔案裡的第一個函式。選到 `doGet` 按執行**不會報錯**，
   > 但也**什麼都不會建立** —— 看起來「執行完畢」，回試算表卻空空如也。
   > 現在的版本已把 `setupSheets` 排到檔案第一個，而且手動執行 `doGet` 會直接跳錯誤提醒。

4. 成功的話會**跳出一個對話框**顯示後台金鑰。回到試算表**重新整理頁面**，
   會看到第一個分頁就是「設定」（金鑰在 B2），上方也多了「**GISA 評分系統**」選單，
   之後查金鑰、清資料、改設定都從這個選單做，不用再進 Apps Script。
5. 「部署 → 新增部署作業 → 類型選『網頁應用程式』」
   - **執行身分**：我
   - **誰可以存取**：**任何人**
   - 按「部署」，複製那串以 `/exec` 結尾的網址。

### 2. 設定前端

把上一步的 `/exec` 網址，貼到**這三個檔案**最上方的 `API_URL`（三個都要貼，缺一個那個頁面就不會動）：

- `index.html`
- `admin.html`
- `links.html`（要能自動同步評審名單就一定要貼）

```js
var API_URL = 'https://script.google.com/macros/s/AKfy....../exec';
```

**為什麼是「推上 GitHub 後」評審才打得開連結**：`index.html` 這些檔案本身只是純文字，
瀏覽器需要一個網址才能打開它們。GitHub Pages 是 GitHub 提供的免費靜態網站代管服務，
會把你 repo 裡的檔案變成一個真正的 `https://...github.io/...` 網址，評審點連結、
手機掃 QR Code 打開的就是這個網址。所以：推上 GitHub → Settings → Pages 啟用代管 →
才會有網址可以用。

推上 GitHub 後，到 repo 的 **Settings → Pages**，Source 選 `Deploy from a branch`，
分支選你要發布的分支、資料夾選 `/ (root)`，儲存。

### 3. 產生評審連結

打開 `links.html`（網址後面加上 `?key=你的後台金鑰`，例如
`links.html?key=xxxx`），會**自動連到試算表抓最新的評審名單**，
網址欄下方會顯示「已同步試算表名單，共 N 位評審」。
每張卡片都有專屬連結、QR Code、複製連結、下載 QR。
按「列印 / 存成 PDF」可做成現場發送用的連結卡。

> 沒帶 `?key=` 也能開，只是會顯示程式內建的備援名單（可能不是最新的）。

也可以在試算表選單「**GISA 評分系統 → 設定 GitHub Pages 網址**」貼上正式網址，
連結就會自動回填到試算表的「評審名單」工作表 C 欄（`setBaseUrl()` 這個函式現在**只能**
從選單呼叫，直接在 Apps Script 編輯器執行會被擋下並提示改用選單——因為編輯器的「執行」
按鈕沒辦法傳參數進去，直接執行只會拿到空值報錯）。

## 操作手冊（可直接發給評審委員）

系統本身附了兩份可列印的說明頁，跟評分頁放在一起：

| 頁面 | 給誰看 | 內容 |
|---|---|---|
| `guide.html` | **評審委員** | 字級放大（內文 19px）的操作說明。第一頁是超大字的三步驟速查，可單獨列印貼在委員桌上；往下是畫面各部位圖解、最終確認流程、以及疑難排解 |
| `admin-guide.html` | **主辦單位** | 試算表選單位置圖解、活動當天的盯場流程、後台六個分頁怎麼看、常見任務逐步驟、重新部署程序、計分規則備忘 |

- 網址就是 `https://你的帳號.github.io/repo/guide.html`（與 `admin-guide.html`）。
- 兩頁上方都有「列印 ／ 存成 PDF」，可印成紙本或存 PDF 用 LINE／Email 發送。
- 評分頁右上角有「操作說明」連結、後台工具列也有一顆，委員或工作人員現場可自行點開。
- `guide.html` 裡的五大構面上限有自動化測試比對評分頁的實際渲染值，
  改權重時若忘了同步更新手冊，測試會直接失敗。
- 兩份手冊是設計成**放在網站上**使用。若把單一檔案下載到電腦再打開（`file://`），
  內容照樣可讀可列印，但「前往後台監控」這類站內連結會自動隱藏並顯示說明——
  因為那些頁面在網站上，本機資料夾裡找不到，點了只會出現「找不到檔案」。
- 從網站開啟手冊時，若瀏覽器已經存過後台金鑰，「前往後台監控」會自動帶上金鑰，
  點一下就直接進後台。

## 二、平常怎麼用

**評審**：點自己的連結 → 選公司 → 填五個構面分數 → 送出評分。
底部隨時可按「**查看所有公司評分**」看目前打過的每家公司總分與名次（彈窗顯示，不用往下滑）。
全部 10 家打完後，系統會自動跳出「最終確認」→ 核對表格、勾選聲明 → 確認送出。
送出後即封存，不可再修改。

> **評審不小心按到最終確認怎麼辦**：主辦單位在試算表選單執行「**解除某位評審的最終確認**」，
> 輸入該評審姓名即可解鎖。評審那邊**不需要做任何事**——下次打開連結（或原本開著的分頁
> 背景同步一次）就會自動恢復成可以修改的狀態，畫面不會再卡在「已完成」。

**主辦單位**：開 `admin.html?key=金鑰`，畫面每 4 秒自動更新：

- **最終成績表** — 系統自動算好的名次、五構面平均、總分平均、已評人數，
  含同分決勝結果說明（例如「同總分，以『創新＋市場』勝出」），可直接匯出使用
- **即時排名** — 各公司平均分、最高／最低／標準差、已評人數
- **評分矩陣** — 評審 × 公司的總分熱區圖，一眼看出誰還沒打、哪家分數分歧大
- **構面分析** — 五個構面的平均與組成
- **評審進度** — 每位評審的進度、平均／全距／標準差（看得出寬嚴），以及「還缺哪幾家」的待補清單
- **評語彙整** — 所有委員意見，可依公司或評審篩選
- **匯出 CSV**、**投影模式**（深色放大，適合現場投影）

> CSV 匯出跟畫面上看到的不是同一份東西：畫面上為了讓你看出「評審是不是特別嚴/特別鬆」，
> 才會放全距、標準差這些統計值；但**匯出的 CSV 是給人直接拿去用的成績單**，
> 只有三張乾淨的表——「最終成績表」（名次＋五構面平均＋總分平均）、
> 「各評審給分總表」（每位評審給每家的總分，迴避會標示「迴避」）、
> 「評分明細」（每筆評分的五構面分數＋評語），不會有標準差這種需要額外解釋的數字。

## 利益迴避（某位評審不評某家公司）

在 Google 試算表的「**迴避名單**」工作表加一列即可，**不用改程式**：

| 評審 | 決選公司 | 備註 |
|---|---|---|
| 汪庭安執行秘書 | 股感媒體科技股份有限公司 | |
| 汪庭安執行秘書 | 峻魁智慧股份有限公司 | |
| 汪庭安執行秘書 | 鉅怡智慧股份有限公司 | 暫定，如確認可評選再刪除此列 |

兩個欄位都是**下拉選單**（只能從既有名單挑，不會打錯字）。加一列＝新增迴避，
刪一列＝取消迴避，改完按選單「重新整理名單快取」立即生效。

**系統會自動處理兩件事**（不需要人工調整分數）：

| 項目 | 原本 | 汪庭安迴避 3 家後 |
|---|---|---|
| 汪庭安應評家數 | 10 | **7**（進度環顯示 `X/7`，評完 7 家即可送最終確認） |
| 股感／峻魁／鉅怡 的評分人數（平均分母） | 8 | **7**（汪庭安不計入） |
| 後台完成度總格數 | 8 × 10 = 80 | **77** |

平均一律用「**實際有評分的人數**」當分母，被迴避的公司不會因此被拉低：

```
某公司 8 位都評：總分加總 640 ÷ 8 = 80.00
被迴避 1 位、7 位評：總分加總 560 ÷ 7 = 80.00   ← 一樣 80，不吃虧
（若錯誤地固定除以 8：560 ÷ 8 = 70.00 ← 系統不會這樣算）
```

評審端的公司列會把那家標示「**迴避**」。按「下一家」時**照樣會停在那一家**（不是無聲跳過），
畫面顯示利益迴避的說明，五個評分欄位與評語框則**轉成灰色鎖住、無法輸入**——
看得到才知道自己為什麼不用評，鎖住才不會有人不小心把分數 key 進去。
後台的評分矩陣也會顯示為「迴避」，與「尚未評分」的斜線格區分開，不會誤判該評審落後。

## 新增評審委員

不用改任何程式：直接在 Google 試算表的「**評審名單**」工作表新增一列（單位、姓名），
存檔即可。`links.html` 開啟時會自動連到試算表抓最新名單，新評審的連結與 QR Code
會自動出現，不需要重新部署或改 `Code.gs`。

## 三、常用維護（試算表上方「GISA 評分系統」選單）

安裝完成後不必再進 Apps Script 編輯器，所有維護都在試算表選單裡：

| 選單項目 | 用途 |
|---|---|
| 顯示後台金鑰 | 忘記金鑰時查詢，會一併顯示後台完整網址 |
| 設定 GitHub Pages 網址 | 輸入網址後自動回填 7 位評審的專屬連結到「評審名單」C 欄 |
| 重新整理名單快取 | 改過「公司名單」「評審名單」或「迴避名單」後，讓變更立即生效 |
| 修復迴避名單下拉選單 | 名單增減後，重新掛上評審／公司的下拉選單 |
| 重新執行安裝 | 可重複執行，不會覆蓋既有資料 |
| 解除某位評審的最終確認 | 評審按錯要重新開放修改時使用 |
| 清空所有評分 | 清空評分與最終確認（**彩排後、正式活動前**執行），會先跳確認視窗 |

> 選單沒出現？把試算表頁面重新整理一次即可（`onOpen` 需要重新載入才會掛上）。

改名單直接編輯「公司名單」／「評審名單」工作表即可，最多 5 分鐘生效，
要立刻生效就用選單的「重新整理名單快取」。

### ⚠ 改過 `Code.gs` 一定要重新部署

Apps Script 有個很容易踩的坑：**在編輯器改完程式並存檔，`/exec` 網址仍然在跑舊版程式碼**。
症狀是畫面完全正常、沒有任何錯誤訊息，但新的權重或迴避設定就是沒生效（靜默出錯）。

正確做法：

> 部署 → **管理部署作業** → 編輯（右上角鉛筆）→ 版本：**新版本** → 部署

**不要**用「新增部署作業」——那會產生一個全新的 `/exec` 網址，
還得回頭把 `index.html`、`admin.html`、`links.html` 三個檔案的 `API_URL` 全部改掉。

為了避免再次靜默出錯，系統已加上版本護欄：後端每次回應都會帶上 `api` 版本號，
若後台偵測到版本比預期舊，會在「最終成績表」最上方跳出紅色橫幅提醒重新部署
（評審端不顯示橫幅，只在瀏覽器主控台留訊息，避免現場評審被技術訊息干擾）。

> 開發備註：日後若再修改計分規則，把 `Code.gs` 的 `API_VERSION` 與
> `admin.html`／`index.html` 的 `EXPECT_API` 同步 +1，護欄才會繼續有效。

## 四、相較去年的改動

### 速度

去年慢的主因是**每個動作都要連一次 Apps Script**：載入名單一次、查看上一筆一次、
查看所有公司一次、最終確認再一次。Apps Script 每次呼叫本身就有 1～3 秒的固定成本。

這版改成：

- **開頁面只連線一次**（`bootstrap`），一次帶回名單 + 該評審已打過的全部分數 + 是否已確認。
  之後「查看評分」「查看所有公司評分」「最終確認」全部用記憶體資料即時渲染，**不再連線**。
- **重新整理秒開** — 先用 localStorage 快取畫面，再於背景跟伺服器同步。
- **送出是樂觀更新** — 畫面立刻反應，網路在背景處理，失敗會自動重試兩次並保留內容。
- **後端寫入直接定位列**，用 rowIndex 快取，命中時省掉整張表的讀取。
- **後台輪詢只讀版本號**，沒有新資料就不傳任何內容，所以 4 秒更新一次也很輕。

### 原有功能全部保留

即時總分、委員意見（300 字）、瀏覽所有公司成績與名次、修改既有評分、
最終確認前的聲明勾選、未評完不得送出、送出後不可修改。

### 新增的防呆

- 評審姓名會比對名單，**不在名單上的 `?judge=` 會被後端拒絕**（去年任何人都能打）
- 分數格式錯誤直接顯示在欄位下方（負分、超過上限、超過兩位小數、非數字）
- 未填完的構面會被指名擋下，並自動捲到該欄位
- 填到一半離開會提醒；未送出的內容存在本機草稿，回來還在
- 公司選擇軌上用顏色標示：已送出（綠）／有未送出變更（黃）／未評分（灰）
- 最終確認表會標出**同分並列**的公司，提醒是否要分出高下
- 最終確認後前後端雙重鎖定，重新開啟頁面也是封存狀態
- 連線失敗有明確提示與「重試」按鈕，不會靜默失敗

### 新增的後台

去年只有試算表；這版多了一個即時儀表板（**最終成績表**、矩陣熱區、構面分析、
評審寬嚴分析、待補清單、評語彙整、CSV 匯出、投影模式）。
資料仍然完整寫進同一份 Google 試算表。

> **手動排名工作表已可停用。** 後台的「最終成績表」會自動計算每家公司的平均分、
> 已評人數（會自動扣掉利益迴避的評審）、名次與同分決勝，並可直接匯出 CSV。
> 試算表裡自建的排名／公式工作表不必再維護（其表頭仍是舊的 `(上限30)`／`(上限10)`，
> 若照舊用會算錯），以後台這張表為準即可。

## 五、備註

- 評分構面與配分（2026 年度，由上而下即為評審填寫順序與試算表欄位順序）：
  市場需求與規模 35、技術門檻 20、產品創新與行銷 30、經營團隊 10、財務狀況 5，
  合計 100 分，可填到小數點後兩位。
  順序由 `apps-script/Code.gs` 與 `index.html` 的 `DIMS` 陣列決定，兩份必須一致；
  改順序後**務必重新部署後端並清空舊評分**（舊資料是照舊欄位順序寫的，會對錯欄）。
- 同分決勝：總分相同 → 比「產品創新＋市場需求」→ 再同 → 比「市場需求」→ 再同 → 比「產品創新」。四項全同才並列。
- 前後端以 JSONP 溝通。選 JSONP 而非 `fetch` 是因為 Apps Script 的 CORS 預檢會多一次來回，JSONP 沒有預檢，實測快 200～400ms。
- 頁面首圖預設用 CSS 重現 2026 官網主視覺的深藍星空＋青綠光束＋金色斜線，不依賴外部圖片。
  若要換成官網的真實圖片，把圖片放進 `assets/`，在 `index.html` 把
  `var BANNER_URL = '';` 改成 `var BANNER_URL = 'assets/你的檔名.jpg';`（或直接貼圖片網址）即可，
  找不到圖片時會自動退回內建版型，不會壞頁面。
- **公開 repo 的風險**：目前 repo 是 Public，`Code.gs` 裡的評審姓名、參賽公司名稱、
  以及 Apps Script 的 `/exec` 網址都是明碼寫在程式裡並會被推上 GitHub，任何看得到
  這個 repo 的人都能看到這些資訊，理論上也能組出 `?judge=某評審姓名` 的網址去代替
  該評審操作（因為目前的「身分驗證」就是姓名字串本身）。真正的分數與最終確認狀態
  不受影響（只存在 Google 試算表，需要金鑰或本人網址才能存取）。免費個人 GitHub 帳號
  的 GitHub Pages 只能用 Public repo，若要完全避免這個風險需要升級付費方案並改成
  Private repo。以本活動的規模這個風險可接受，活動結束後可用選單「清空所有評分」
  清除當屆分數資料，降低長期外流影響。
